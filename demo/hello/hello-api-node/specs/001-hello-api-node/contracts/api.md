# API Contract – HelloAPI REST Endpoints

**Version**: 1.0.0  
**Source**: `specs/001-hello-api-node/openapi.yaml`  
**Status**: Production (Finalized Phase 1)

---

## Overview

HelloAPI exposes **3 REST endpoints** over HTTP. All endpoints:
- Use JSON request/response format
- Return structured error responses on failure
- Support CORS (for browser clients)
- Are stateless (no session required)

---

## Endpoint 1: Generic Greeting

### `GET /api/hello`

**Purpose**: Get default greeting message

**Request**

```http
GET /api/hello HTTP/1.1
Host: api.example.com
```

**Response: 200 OK**

```json
{
  "message": "Hello World"
}
```

**Use Case**: 
- Health check that also returns data (quick validation)
- Default response when user doesn't specify a name
- Testing API availability with minimal request

**Rules**:
- No parameters required
- No authentication required
- Stateless (always returns same response)

---

## Endpoint 2: Personalized Greeting

### `GET /api/hello/{name}`

**Purpose**: Get greeting message for specific person

**Path Parameters**

| Parameter | Type | Required | Constraints | Example |
|-----------|------|----------|-------------|---------|
| `name` | string | ✅ Yes | minLength: 2, maxLength: 25, pattern: `^[a-zA-Z ,.'-]+$` | "Philippe" |

**Request Examples**

```http
GET /api/hello/Philippe HTTP/1.1
Host: api.example.com
```

```bash
# CLI Examples
curl https://api.example.com/api/hello/Philippe
curl https://api.example.com/api/hello/Jean-Marie
curl https://api.example.com/api/hello/O'Brien
```

**Response: 200 OK**

```json
{
  "message": "Hello Philippe"
}
```

### Validation Rules

**Input Processing**:
1. **Trim whitespace** from name (leading/trailing spaces removed)
2. **Validate** against constraints:
   - Min length: 2 characters (no single letters)
   - Max length: 25 characters
   - Allowed characters: Letters (a-z, A-Z), spaces, comma, period, hyphen, apostrophe
   - Invalid characters: Numbers, special symbols (@, #, $, etc.)

**Validation Examples**:

| Input | Trimmed | Valid? | Reason |
|-------|---------|--------|--------|
| `Philippe` | `Philippe` | ✅ | Alphanumeric, 8 chars |
| ` Jean ` | `Jean` | ✅ | After trim: 4 chars |
| `a` | `a` | ❌ | After trim: 1 char (min 2) |
| `Marie-Claire` | `Marie-Claire` | ✅ | Hyphen allowed |
| `O'Brien` | `O'Brien` | ✅ | Apostrophe allowed |
| `Jean123` | `Jean123` | ❌ | Numbers not allowed |
| `Jean@Paul` | `Jean@Paul` | ❌ | @ symbol not allowed |
| `a b c d e f g h i j k l m n o p` | `a b c d e f g h i j k l m n o p` | ❌ | 31 chars (max 25) |

**Error Handling** (400 Bad Request):

```json
{
  "timestamp": "2026-04-24T10:30:00.000Z",
  "status": 400,
  "error": "Bad Request",
  "message": "name must be at least 2 characters",
  "path": "/api/hello/a"
}
```

**Error Messages** (auto-generated by Zod validation):
- `"name must be at least 2 characters"` — parameter too short
- `"name must be at most 25 characters"` — parameter too long
- `"name format is invalid"` — contains disallowed characters

**Edge Cases**:

| Case | Handling |
|------|----------|
| Unicode letters (é, ñ) | ❌ Rejected (pattern only allows ASCII a-z, A-Z) |
| Leading/trailing spaces | ✅ Trimmed before validation |
| Multiple spaces in middle | ✅ Allowed (e.g., "Jean Paul" is valid) |
| Empty string | ❌ Rejected (min 2 chars) |
| Null | ❌ Rejected (type error → 400) |
| Numeric string ("123") | ❌ Rejected (no digits allowed) |

**Status Codes**:
- `200`: Success
- `400`: Validation error (bad parameter)
- `500`: Server error

## Endpoint 3: Health Check

### `GET /health`

**Purpose**: Kubernetes liveness probe + readiness check

**Request**

```http
GET /health HTTP/1.1
Host: api.example.com
```

**Response: 200 OK**

```json
{
  "status": "healthy",
  "uptime": 3600
}
```

**Response: 503 Service Unavailable** (if unhealthy)

```json
{
  "status": "degraded",
  "uptime": 120
}
```

### Usage Context

**Kubernetes Liveness Probe**:
```yaml
# kubernetes/deployment.yaml
livenessProbe:
  httpGet:
    path: /health
    port: 3000
  initialDelaySeconds: 10
  periodSeconds: 10
  timeoutSeconds: 5
  failureThreshold: 3
```

**Health Status Meanings**:
- `"healthy"`: Application is running normally, ready for requests
- `"degraded"`: Application is running but experiencing issues (e.g., DB connection slow)

**Monitoring Integration**:
```bash
# Prometheus scrape every 10 seconds
curl http://localhost:3000/health

# Expected for healthy app:
# {"status":"healthy","uptime":3600}
```

**Status Codes**:
- `200`: Application is healthy (accepts `healthy` or `degraded`)
- `503`: Application is down (critical errors)

## Error Response Format

**All 4xx/5xx responses** follow this structure:

```json
{
  "timestamp": "2026-04-24T10:30:00.000Z",
  "status": 400,
  "error": "Bad Request",
  "message": "name must be at least 2 characters",
  "path": "/api/hello/a"
}
```

**Fields**:

| Field | Type | Description |
|-------|------|-------------|
| `timestamp` | ISO 8601 string | When error occurred (UTC) |
| `status` | integer | HTTP status code (400, 404, 500, etc.) |
| `error` | string | HTTP status text (Bad Request, Not Found, etc.) |
| `message` | string | Detailed error description |
| `path` | string | Request path that caused error |

**Auto-Generation**: Error responses are **generated by middleware**, not manually constructed:
- Validation errors (400) generated by Zod error handler
- 404 errors generated by Express router
- 500 errors generated by error middleware

**Client Handling Example**:
```typescript
// TypeScript client code
try {
  const response = await fetch('https://api.example.com/api/hello/a');
  if (!response.ok) {
    const error = await response.json();
    console.error(`Error ${error.status}: ${error.message}`);
    // Output: "Error 400: name must be at least 2 characters"
  }
} catch (e) {
  console.error('Network error:', e);
}
```

## CORS Configuration

**Allowed Origins**: Configurable per environment

```typescript
// src/config/express.ts (pseudo-code)
app.use(cors({
  origin: process.env.CORS_ORIGINS?.split(',') || 'http://localhost:3000',
  credentials: true,
  methods: ['GET', 'HEAD']
}));
```

**Default (Development)**:
- Allow `http://localhost:*` (all local ports)
- Allow `http://127.0.0.1:*`

**Production** (set via `CORS_ORIGINS` env var):
- Configure specific frontend domains (e.g., `https://www.example.com`)

## Rate Limiting

**Phase 1 (MVP)**: Not implemented  
**Phase 2+**: Can add `express-rate-limit` middleware

**Proposed rates** (POST-MVP):
- `/api/hello`: 100 requests per minute per IP
- `/api/hello/{name}`: 100 requests per minute per IP
- `/health`: 1000 requests per minute per IP (exclude from limits)
